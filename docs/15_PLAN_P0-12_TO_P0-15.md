# 15 — Plan P0-12 → P0-15 (Auth, Tool Authorization, Speech-to-Text)

Ngày lập: 2026-08-27 · Demo: **2026-09-03** · Ngân sách: **6 ngày + 1 buffer**

## 1. Mục tiêu

Ba tính năng mentor yêu cầu bổ sung sau khi P0-10 đóng:

1. **Login theo role** — nhiều user, nhiều vai trò.
2. **Phân quyền tool ở MCP Server** — RM **không** được gọi `delete_customer`, và **ghi log** việc từ chối.
3. **Speech-to-text** — push-to-talk, transcribe bằng Gemini, RM xác nhận text trước khi gửi.

Deliverable trọng tâm của (2) **không phải "chặn được"** mà là **dòng log ghi lại việc từ chối** — đó là thứ mentor muốn nhìn thấy.

**8 tool** cho mọi role. Authorization xảy ra ở **`tools/call`**, không phải ở discovery.

- Một điểm thực thi duy nhất, ở đúng boundary. Lọc ở discovery là UX, không phải bảo mật.
- Nếu ẩn tool khỏi RM thì lời gọi **không bao giờ xảy ra**, và **không có gì để ghi log** — trái
  đúng thứ mentor yêu cầu.

  không có yêu cầu nào bắt `tools/list` phải phản ánh quyền của caller.

**Hệ quả:** mọi bước demo phải kiểm bằng **kết quả `tools/call`**, không phải bằng **số tool trong
`tools/list`**. Hai điều đó không thể cùng đúng.

## WP4 — Speech-to-text (1,5 ngày)

### Kết quả Spike A — đã chạy 2026-08-27, ĐÃ CHỐT

Đo thật trên Chrome console với audio 8 giây tiếng Việt:

| Model | Kết quả |
| --- | --- |
| `gemini-3.5-flash-lite` | ❌ Trả rác — `"Hải Phòng"`, `"vợ"` |
| **`gemini-3.5-flash`** | ✅ `"Tìm hồ sơ khách hàng C U S 0 0 0 1"` |
| `gemini-3-flash-preview` | ✅ `"Tìm hồ sơ khách hàng CUS0001."` (tốt hơn, nhưng là preview) |
| `gemini-omni-flash-preview` | ⛔ HTTP 429 — free tier quota = 0 |
| `gemini-2.5-flash`, `gemini-2.5-pro` | ⛔ HTTP 404 — không còn mở cho user mới |

**Chốt:**

- **Định dạng: `audio/webm;codecs=opus` dùng được.** KHÔNG cần ghi WAV, không cần convert.
  Biến "container" đã bị loại — đừng tốn thời gian vào nó nữa.
- **Model: `gemini-3.5-flash`** (bản đầy đủ, không phải `-lite`, không phải preview).
  Đây là model **chỉ dùng cho transcribe**; chat/email/call-script vẫn giữ `gemini-3.5-flash-lite`.
  Thêm option riêng `SPEECH_MODEL_ID`, **không** đụng `EmailGenerationOptions.ModelId`.
- **Kích thước: ~14 KB/giây** (8 giây ≈ 112 KB). Trần 30 giây ≈ 420 KB → đặt giới hạn **1 MB**.

### Chuẩn hoá transcript — bắt buộc

Model trả mã khách hàng dưới dạng đọc rời: `"C U S 0 0 0 1"` hoặc `"CUS0001"`.
Cần bước chuẩn hoá phía client trước khi điền vào ô input:

1. Bỏ khoảng trắng giữa các ký tự đơn lẻ liên tiếp: `C U S 0 0 0 1` → `CUS0001`
2. Chèn gạch nối theo `CustomerIdFormat`: `CUS0001` → `CUS-0001`
3. Cũng xử lý dạng đọc số tiếng Việt: `cus không không không một` → `CUS-0001`

Nếu không chuẩn hoá, `InputGuard` sẽ trả `CUSTOMER_ID_REQUIRED` và RM phải sửa tay mỗi lần.

### Luồng

```
Push-to-talk (giữ nút) → MediaRecorder ghi audio
   → POST /api/transcribe (multipart)
   → Gemini transcribe
   → Trả text về, ĐIỀN VÀO Ô INPUT (chưa gửi)
   → RM đọc, sửa nếu cần, bấm Gửi
   → /api/chat như bình thường
```

**Bước RM xác nhận là một control PII, không phải tiện ích UX.** Nó cho RM cơ hội bỏ tên khách hàng và thay bằng mã trước khi text đi tiếp.

### Tạo mới

| File | Nội dung |
| --- | --- |
| `src/CrmCopilot.Web/Speech/TranscribeEndpoint.cs` | `POST /api/transcribe`, `[Authorize]`, giới hạn kích thước + thời lượng |
| `src/CrmCopilot.Web/Speech/GeminiTranscriber.cs` | Gọi Gemini với audio inline part |

### Sửa

| File | Thay đổi |
| --- | --- |
| `wwwroot/js/app.js` | Nút micro, `MediaRecorder`, gọi `/api/transcribe`, điền text vào input |
| `wwwroot/css/app.css` | Trạng thái đang ghi âm |
| `Pages/Index.cshtml` | Nút micro + **banner cảnh báo audio rời máy** |

### Ràng buộc

- Giới hạn **30 giây** và **~5 MB** mỗi lần ghi
- Chỉ nhận `audio/*`
- **Không lưu file audio xuống đĩa** — xử lý trong bộ nhớ rồi bỏ
- Log chỉ ghi `durationMs`, `bytes`, `status` — **không** ghi transcript
- Banner UI: *"Nhận dạng giọng nói gửi audio tới Gemini. Không đọc thông tin nhạy cảm."*

### Acceptance

- [ ] Nói *"tìm hồ sơ khách hàng cus không không không một"* → ô input hiện text tiếng Việt có dấu
- [ ] Text **không tự động gửi** — RM phải bấm Gửi
- [ ] Chưa login → `/api/transcribe` trả **401**
- [ ] Audio quá 30 giây → từ chối có kiểm soát
- [ ] Log **không** chứa transcript

### ~~Spike B — JWT qua `HttpClientTransport`~~ ✅ ĐÃ XONG 2026-08-27

Đo trên `ModelContextProtocol` 2.2.0 (package đã cài + source):

- `AdditionalHeaders` là `IDictionary<string,string>?`, **cố định lúc dựng transport** — không đổi được theo từng request.
- `RequestOptions` per-call **không có** chỗ đặt HTTP header.
- Constructor nhận `HttpClient` của mình → **`DelegatingHandler` là đường đi khả thi**.
- SDK có **`WithRequestFilters().AddCallToolFilter()`** — dùng cái này thay vì chép kiểm quyền vào 8 file `*Tools.cs`.

**Ba cạm bẫy đã phát hiện:**

1. `EnableStandaloneGetStream` mặc định `true` — GET stream chạy **ngoài** request context nên không có token ⇒ phải đặt `false`.
2. `OwnsSession` gửi `DELETE` lúc dispose.
3. `initialize` lazy ⇒ handshake mang token của **user đầu tiên**.

**Quyết định cho demo:** tạo **`McpClient` mới cho mỗi request** thay vì singleton. Cách này triệt tiêu cả ba cạm bẫy cùng lúc, đổi lại thêm một `initialize` + `tools/list` mỗi lượt chat — chỉ vài chục ms trên localhost. Bản `DelegatingHandler` + singleton + `IHttpContextAccessor` là cách đúng cho production, ghi backlog.
